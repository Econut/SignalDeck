# UNIWA P8 aviation AM capability check

Read-only investigation, 28 October 2026. Decision: no supported built-in aviation AM reception path found; do not add an AM mode or attempt an undocumented live test.

- Exact live module identity was previously verified by checksummed version response: DMR003BN.UV4P.V026 (docs/p8-rootfree-progress.md).
- Stock Intercom ChannelActivity.java lines 206–209 sets UHF 400–480 MHz and VHF 136–174 MHz input limits. These are application limits, not a measurement of the synthesizer/front-end or guaranteed sensitivity. UNIWA's current manufacturer specification lists UHF 400–470 MHz and optional VHF 136–174 MHz: https://www.cwelltech.com/product/uniwa-p8-android-14-smart-zello-mobile-walkie-talkie/ . Most of 118–137 MHz is outside that advertised VHF range; overlap at 136–137 does not establish AM support.
- Re-examined stock y2.c analogue packet fields (0x23): RX/TX frequency, bandwidth, power, squelch, RX/TX subtones, power-save, receive volume and duplicated monitor field. No AM/FM demodulation selector. Separate digital configuration is 0x22. Stock resources expose analogue/digital modes; targeted source/resource searches found no aviation/AM demodulation command or mode. Bandwidth and monitor settings are not modulation modes.
- No authoritative protocol document specific to BN.UV4P.V026 was located in this bounded search. Existing reverse-engineered protocol evidence supports FM/DMR, not a complete proof of all undocumented module features.
- Read-only recheck of bundled MCU binaries: dmr_003.bin 303832 bytes, DMR003N.UV4P.V011, SHA-256 d2a8d07e280980e0c2f6dfdd75cd92674312e81d56eda340effdf9b366a3e2cb; image/dmr_003.bin 379964 bytes, DMR003N.UV4P.V002, SHA-256 d404d7ecf3bb978acc3dfbd8a4125747b53c46000480aeb48465f41e6e495d5b. Printable-string searches found no AM/aviation indication. These are older N variants, not the installed BN V026; absence of strings is not proof of hardware impossibility. The Android factory ROM is not an independently verified dump of V026 module firmware or its calibration.
- Existing discovery report plus read-only ADB inventory: additional /dev/fm path; ro.vendor.fm.platform=mt6631; /vendor/lib/modules/fmradio_drv_mt6631.ko; stock factory FMFragment launches com.android.fmradio/.FmMainActivity. This is evidence of a separate FM-broadcast path, not aviation AM. USB enumeration showed only the root hub, no attached SDR. No additional AM receiver or raw RF/IQ interface identified; this is not a board teardown/schematic-level exclusion.
- Existing UART supplies already-demodulated 8 kHz voice PCM. An Android audio decoder cannot recover RF AM envelope information that the module's FM path has discarded. Weak accidental slope detection would not establish proper airband reception.

No UART commands, tuning, GPIO changes, transmission, flashing or calibration changes performed for this check. Protected firmware/backups unchanged. No live aviation test: prerequisite of a supported AM command was not met. Retain current frequency/modulation limits and return to SignalDeck development.

Only useful factory follow-up: ask whether this exact BN.UV4P.V026 hardware has an AM detector, its specified RX-only tuning limits, and a documented AM-select command. Without that evidence, aviation reception requires a separate AM-capable receiver (an external receiver integration would be separate work).
